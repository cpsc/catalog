---
title: 各 Kubernetes 發行版的差異
description: 比較各 Kubernetes 發行版的已知差異，確認元件與範本需要的設定。
source: "7c67fb3054d1"
---

元件與範本在 kind 上測試，Kubernetes 小版本與 Zeabur Installer 固定的 RKE2 版本相同。`single-node` profile 使用 1 個節點，`multi-node` profile 使用 3 個節點。profile 是這兩種部署方式的設定組合。其他發行版的行為相同，但有以下已知差異。

- **k3s**：啟動時加上 `--disable=traefik,metrics-server`，讓 Traefik 與 metrics-server 都由各自的 chart 安裝。k3s 會安裝自己的 Gateway API CRD。在 NAT 後方執行時，不要設定 `node-external-ip`，否則 Traefik 會失去用戶端位址。
- **KubeSolo**：預設 StorageClass 會在 PersistentVolumeClaim 刪除後保留磁碟區及其資料。在 Ubuntu 上，將 `/etc/hosts` 中的主機名稱對應到節點 IP。若對應到 127.0.1.1，API server 會拒絕代理連線至 kubelet。KubeSolo 的節點沒有 control-plane 標籤。
- **Longhorn**：每個節點都需要安裝 open-iscsi、啟動 `iscsid`，並具備 `iscsi_tcp` 模組與 NFSv4 用戶端。不要讓 multipathd 管理 Longhorn 使用的磁碟。詳細需求見 Longhorn 元件檔案中的註解。CI 會在 kind 節點內安裝這些相依項目。
- **發行版限制與 KubeSolo 測試**：元件的 `distributions` 欄位會限制適用的發行版，例如 system-upgrade-controller 適用於 k3s 與 RKE2。`kubesolo` e2e profile 會略過 `distributions` 清單未包含 `kubesolo` 的元件。這個測試 profile 涵蓋的 capability（用途類別）是 `ingress`、`certificates` 與 `container-registry`，設定見 [`config/kubernetes.yaml`](https://github.com/zeabur-oss/catalog/blob/main/config/kubernetes.yaml)。
- **範本儲存空間**：範本不指定 StorageClass，因此磁碟區會使用叢集的預設 StorageClass。若叢集沒有預設 StorageClass，PersistentVolumeClaim 會停留在 `Pending`。
